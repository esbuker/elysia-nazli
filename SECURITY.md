# Security

Please do not disclose security vulnerabilities publicly.

## Reporting

Open a GitHub issue marked as a security concern with limited details first. Share only enough information to establish that a security review is needed.

Do not include:

- Secrets, tokens, API keys, or credentials
- Private infrastructure details
- Full exploit instructions
- Personal data or production logs

## Safe report contents

Helpful, low-risk details include:

- A short description of the affected behavior
- Package version
- Bun and Elysia versions
- Store type involved, if relevant
- Whether the issue affects configuration, key generation, headers, store failure behavior, or request blocking

The maintainer can then coordinate next steps privately if more detail is needed.
